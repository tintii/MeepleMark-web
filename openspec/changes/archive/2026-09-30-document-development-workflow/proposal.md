## Why

The repository now has a Codex development skill, but its documentation-maintenance expectations need to be explicit and discoverable. The root README should stay focused on the product and quick start while detailed contributor and agent guidance lives under `docs/`.

## What Changes

- Require development work to update relevant README and documentation content when behavior, setup, operations, or architecture changes.
- Define the root README as a concise product overview and documentation index rather than a home for detailed technical guidance.
- Document the repo-local Codex, Ponytail, OpenSpec, changelog, and setup workflow in the development guide.

## Capabilities

### New Capabilities

- `development-workflow-documentation`: Defines how repository changes keep user-facing and technical documentation current and organized.

### Modified Capabilities

None.

## Impact

The change affects the repo-local MeepleMark development skill, `README.md`, `docs/development.md`, and the unreleased changelog. It does not change application runtime behavior or dependencies.
